# Verdict: REFUSED

Reviewed commit `0d14cd4237a1c0824b59fc768360bccee39f49ae` against `HEAD~1`. Concurrent uncommitted changes were excluded.

1. **F-1 — INFO — Verifiability passes.** Index construction verifies every package and derives variant digests from canonical package bytes (`HEAD:src/main/java/org/seventeenthsecond/uaofoundry/registry/FoundryRegistry.java:349-362`, `:414-437`). ENRICH then requires an existing `fromVariant`, an occurrence of the subject in `toPackageId`, the declared `toVariant` in that package, and a byte-derived strict assertion superset (`:613-648`, `:655-662`). Journal records are also content-address checked on every read (`:540-558`). Current variants are selected only from occurrence-derived digests (`:923-944`). Therefore, a journal record cannot make an unsupported variant current.

2. **F-2 — HIGH — `enrich()` is not atomic for every post-registration refusal.** The package is registered at `FoundryRegistry.java:716`; operation construction occurs at `:717`; the rollback `try` begins only at `:718`. Construction can refuse empty reason codes or blank justification/timestamp (`HEAD:src/main/java/org/seventeenthsecond/uaofoundry/identity/IdentityOperation.java:116-124`). In that case the enriching package and rewritten index remain, with no ENRICH record. This directly contradicts ADR-0007’s rollback guarantee (`HEAD:docs/ADR-0007-IDENTITY-ENRICHMENT.md:36-38`).

3. **F-3 — INFO — Individual semantic and graph refusals pass by inspection.** Missing `fromVariant` and missing/wrong target occurrences are refused at `FoundryRegistry.java:622-629`; rewording/non-superset and assertion no-op at `:630-661`; identical variants at `IdentityOperation.java:158-164` and `FoundryRegistry.java:709-714`; forks and cycles at `FoundryRegistry.java:821-842`. Thus the specific guards exist, but Question 2 fails overall because of F-2.

4. **F-4 — INFO — Backward-compatible index and reuse behavior passes.** With no ENRICH edges, `current` equals the pre-existing variant set, and `currentVariant`/`variantHistory` are omitted (`FoundryRegistry.java:923-945`). This is equivalent to the parent implementation at `HEAD~1:src/main/java/org/seventeenthsecond/uaofoundry/registry/FoundryRegistry.java:770-788`. In `ReuseAnalyzer`, the new behavior is conditional on `currentVariant` being a string; when absent, the old occurrence-set logic remains (`HEAD:src/main/java/org/seventeenthsecond/uaofoundry/reuse/ReuseAnalyzer.java:68-88`).

5. **F-5 — INFO — Existing operation IDs remain unchanged.** The legacy factory supplies `null` enrichment (`HEAD:src/main/java/org/seventeenthsecond/uaofoundry/identity/IdentityOperation.java:96-100`), and `projection()` adds the new field only when non-null (`:229-242`). The remaining projection is identical to the parent (`HEAD~1:src/main/java/org/seventeenthsecond/uaofoundry/identity/IdentityOperation.java:172-184`). Existing SUPERSEDE, RETIRE, MERGE, and SPLIT IDs therefore do not change.

6. **F-6 — MEDIUM — The tests are only partially adequate.** The first test meaningfully exercises strict-superset acceptance and both current and stale reuse outcomes (`HEAD:src/test/java/org/seventeenthsecond/uaofoundry/registry/PersistentIdentityRegistryTest.java:188-220`). The second meaningfully exercises rewording and no-op refusal (`:223-242`). The third does **not** exercise the journal fork guard: it calls `enrich()`, which chooses the current variant, and is refused as a non-superset before a second outgoing edge exists (`:245-258`). Its unsupported-record check is meaningful, but the final history assertion uses the pre-refusal `identity` snapshot and is tautological as a rollback postcondition (`:260-268`). No new test reaches the F-2 failure-after-`register()` path.

7. **F-7 — HIGH — Significance export can return superseded assertions.** Enrichment deliberately marks an identity `SINGLE_VARIANT` while retaining multiple occurrences (`FoundryRegistry.java:933-952`). `significanceInputs()` nevertheless selects the first non-empty occurrence without matching its digest to `currentVariant` (`:276-289`); occurrences are ordered by package ID, not succession (`:920-921`). Consequently, `A_x` can contain historical rather than current assertions—the exact stale-state problem ENRICH is intended to resolve.

**Closure:** Refusal rests on two behavioral defects: incomplete rollback after successful package admission and stale-variant significance export. Move operation construction inside the rollback boundary or validate all operation metadata before registration, select significance assertions by `currentVariant`, and add genuine fork plus post-registration rollback tests. The immutable-byte verification, legacy index compatibility, reuse fallback, and legacy content addresses otherwise satisfy the requested laws.
